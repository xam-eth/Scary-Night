## What reads at industry level

- **Art direction & grade.** Candlelit pools on near-black, blood-red accent
  system, red-carpet focal room, portrait silhouettes on walls: cohesive
  gothic identity, consistent across all screens. Panic grading (red wash,
  "PANIC" header, broken-door stack top-right) escalates legibly.
- **Typography system.** Letter-spaced display serif + mono stat lines with a
  strict hierarchy — menu/intro/death/victory look shipped-product grade,
  matching the restraint of titles like *Dredge* / *Papers, Please* meta UI.
- **Narrative HUD language.** Event captions ("THE HOUSE GOES QUIET.",
  "IT DID NOT WAIT FOR AN INVITATION.") replace icon-soup: tension
  communication through text + sound is the *Don't Starve* / *LANDBOT* lane
  and it pays off here.
- **Meta screens.** Death screen (headline, survived/best/nights, shard
  payout, three CTAs) and victory (dawn light shafts, NEW RECORD, stat
  ledger) are complete loops — the "reward for losing" loop is exactly the
  mobile-midcore pattern (roguelite meta + shards).
- **Accessibility above baseline for the genre:** captions toggle, invert
  panic flash, flash-effect slider, camera-shake slider — many shipped
  horror indies don't offer half of this.
- **Touch layout:** 5 context buttons + stick verified at 412x915 /
  900x420 / 1280x720; desktop HUD stays clean (no phantom buttons).

## Gaps vs industry standard (prioritized)

**P0 — shipping-blocking-ish**
1. **Character identity mismatch on menu:** the title silhouette is the old
   procedural vampire while the in-game character is now the GLB. The GLB
   runtime already exposes `renderMenu()`; compose the live idle GLB into
   menu + victory poses. One identity, one asset.
2. **Victory screen vertical overflow at 1280x720:** the "MAIN MENU" button
   clips at the bottom edge; small phones in landscape (< 500 css px tall)
   will break harder. Add screen-space clamping/scale-to-fit on the panel.
3. **Settings slider row spacing:** right-aligned labels collide with the
   track ("CAMERA SHAKE"/"FLASH EFFECTS" overlap the bar). Reserve a fixed
   label column (`x = sliderLeft - 24`) or stack label above the track.

**P1 — feel & readability**
4. **Player readability in blackout/low-blood states:** the halo keeps her
   found, but at 8% blood the figure is ~5% of screen height. The GLB at 74px
   helps; consider +12% size and a faint ground ring in `blackoutT`.
5. **Event captions sit on the play area over the rug.** Add a 55%-opacity
   4px-black scrim behind caption lines, or park the stack above the HUD
   blood row.
6. **Interactable legibility at range:** doors/windows outside candlelight are
   invisible until close; industry top-down horror (e.g. *Project Zomboid*
   night mode) uses a subtle edge-highlight on interactables. Add a 1px cold
   rim on entrances within earshot of a knock.
7. **Knock compass (top-right dial) has no legend on first use** — it's the
   only spatial-audio proxy visually; tie its first appearance to a caption
   ("the dial points where it knocks").

**P2 — polish**
8. Menu buttons lack visible focus state in captures (hover exists, but a
   keyboard/gamepad focus ring would match console UX).
9. Death screen has no "cause" line (`the hunger took you` exists in the kill
   path) — surface it under the headline; it teaches.
10. Upgrades screen rank pips are monochrome; the "0/5 recorded" collection
    grid has no silhouette teasers — classic blind-box loss for mobile.

## PASS 3 — Input plumbing (real mouse/keyboard, live browser) — 2026-09-23

Report from the user: *"semua tombol tidak berfungsi"*. Reproduced with a real
Chromium clicking real buttons: the page rendered fine, zero console errors,
the loop was alive — and no button on any screen answered a mouse click.
New permanent test: `node tools/clicktest.mjs` (18 checks, deterministic
frame-pumping so headless rAF starvation can't fake results).

### Bugs found — all PRE-EXISTING since the base checkout, none introduced by v1.0
1. **Every pointer click on a menu button was swallowed (P0).** `game.update()`
   wiped `game.ui` at its start, but immediate-mode buttons register during
   `render()`, which runs after update — so `handleUIInput()` always
   hit-tested an empty array. Mouse and touch alike. The `mouse.clicked`
   branch couldn't save it either: `input.update()` consumes that flag before
   `handleUIInput()` reads it. **Fix:** the ui wipe moved to the top of
   `render()`; left-press now posts the same one-shot `uiTap` channel touch
   uses; taps spent during 'playing' are cleared so they can't pop a menu
   button later.
2. **ESC/P could not pause during gameplay (P1).** The pause toggle lived in
   `handleUIInput()` *behind* the `!inMenu` early return — reachable only from
   menus, i.e. exactly never for its main use. **Fix:** toggle moved before
   the guard.
3. **Pause → SETTINGS → BACK black-holed the game (P1).** The pause menu passed
   `from='pause'`, not a real screen id; BACK called `setScreen('pause')` and
   nothing drew or updated there. HOW TO SURVIVE had the same typo. **Fix:**
   both now pass `'paused'`.
4. **Night start hung on audio (P2, latent).** `beginNight()` ran the whole
   transition inside `Audio.unlock().then(...)`; a suspended/rejecting
   AudioContext (audio-less browsers, autoplay quirks) silently ate it — PLAY
   and TRY AGAIN looked dead. **Fix:** state machine is synchronous; unlock +
   volume is fire-and-forget with `.catch`; same catch added to the gesture
   handler in `main.js`.

### Method note
Headless @sparticuz Chromium throttles rAF (0–8fps, bursty). Input tests that
sleep on wall-clock time will produce fake failures. `clicktest.mjs` pumps
`update()+render()` from the harness after each real event — deterministic,
no timing races. (This fake-out burned two debug rounds before the real bug
above #1/#3 were even visible.)
